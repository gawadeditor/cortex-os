# خطة نقل المصنع لسيرفر (الإنتاج بعيد عن جهاز المشغّل)

آخر تحديث: 2026-10-11. مكمّلة لـ [SERVER_PLAN.md](SERVER_PLAN.md) (اللي نقلت Postiz بس) و[MULTI_TENANT_PLAN.md](MULTI_TENANT_PLAN.md).

## ليه

- المصنع كله (worker، القاعدة، الـ pipeline، ffmpeg، البورتال، الداشبورد) شغال على ماك المشغّل. لو الماك وقف أو اتفصل، الإنتاج والبورتال بيقفوا **لكل العملاء**.
- كل عميل جديد بيزوّد الحمل على نفس الجهاز، والـ render بياخد CPU طول الـ run.
- الهدف: جهاز إنتاج شغال 24 ساعة، والماك يبقى للتطوير بس.

## اللي بيتنقل واللي بيتغير

| الحاجة | الوضع الحالي | على السيرفر |
|---|---|---|
| worker + pipeline + ffmpeg | LaunchAgent على الماك | systemd service (أو container) |
| القاعدة (`hypogeum.db` 76MB + `portal_auth.db`) | ملف SQLite محلي | **تفضل SQLite على قرص السيرفر** (كاتب واحد). مفيش داعي لـ Postgres دلوقتي |
| الأصول المؤقتة `.hypogeum-assets` (1.1GB) | محلي | قرص السيرفر |
| الأرشيف `/Volumes/Archive/Cortex` (9.9GB ويزيد) | NAS على SMB | **Cloudflare R2** (أو Backblaze B2). محتاج تعديل في `archive_relocation` عشان يكتب على object storage بدل مسار ملفات |
| البورتال + الـ webhook receiver + التانل | LaunchAgents على الماك | systemd + نفس تانل `cortex-hooks` (نفس الـ hostnames، مفيش redirect URI يتغير) |
| الداشبورد المحلي | بدون login، على 127.0.0.1 | يفضل **خاص**: على السيرفر لكن متاح من Tailscale بس. مش على النت العام |
| الموسيقى VODER (14GB) | محلي على الماك | **مش هيشتغل على سيرفر من غير GPU.** على السيرفر نرجع `MUSIC_PROVIDER=elevenlabs` (بيتحاسب)، أو نسيب VODER على الماك كخدمة منفصلة (مش مفضّل: ده بيرجّع الاعتماد على الماك) |
| ffmpeg | من غير libass (الكابشن المحروق بيتخطى) | ffmpeg لينكس فيه libass، فالكابشن المحروق **يشتغل** (مكسب جانبي) |
| الأسرار (`.env`، الـ vault، مفتاح التوقيع) | ملفات على الماك | تتنقل بـ `scp` مش GitHub. مفتاح vault بيتحفظ نسخة منه خارج السيرفر |
| Postiz | سيرفر Hostinger الحالي (8GB، بياخد 2.75GB) | **يفضل مكانه.** السيرفر الجديد منفصل عشان الـ render ما يزاحمش النشر |

## شروط لازم تتحل قبل النقل

1. إصلاح قفل القاعدة في `submission_gate.py` (اتعمل وغير committed). من غيره كل عميل زيادة بيزوّد "database is locked".
2. مسار الأرشيف: `archive_relocation` و`ensure_archive_root_mounted()` متعمولين للـ NAS. لازم طبقة تخزين (محلي / R2) بدل افتراض mount.
3. أي مسارات `/Users/gawadeditor/...` متكتبة في الكود أو الـ plists لازم تتحول لـ Config.
4. اختبار تشغيل كامل على السيرفر بـ `MUAPI_DRY_RUN=true` الأول، وبعده episode حقيقي واحد.

## المراحل

1. **تجهيز السيرفر**: يوزر مش root، SSH بمفتاح، ufw (SSH بس)، fail2ban، unattended-upgrades، swap، Python 3.11، ffmpeg، Tailscale. (نفس سكريبتات `scripts/server/bootstrap_stage{1,2}.sh` مع تعديلات.)
2. **طبقة التخزين**: تنفيذ backend لـ R2 في الأرشيف + اختبارات. نسخ الأرشيف الحالي (9.9GB) لـ R2.
3. **تشغيل بالتوازي بدون إنتاج**: نسخة من القاعدة، الـ worker بـ `--dry-run`، التأكد إن كل الـ checks سليمة.
4. **تبديل**: نوقف الـ worker على الماك (بعد ما أي run شغال يخلص)، ننقل القاعدة الأخيرة، نشغّل الـ worker والبورتال والـ webhook والتانل على السيرفر، ونوقف الـ LaunchAgents على الماك.
5. **التأكد**: episode حقيقي كامل، تسجيل دخول عميل على البورتال، تنبيه Telegram، نشر على Postiz.
6. **النسخ الاحتياطي والمراقبة**: نسخة ليلية للقاعدة والـ vault إلى R2 (آخر 14 يوم) + تجربة restore شهرياً، وhealthchecks.io، وتنبيه Telegram لو الـ worker وقف.
7. **الرجوع**: الماك يفضل أسبوع جاهز (نفس الكود، القاعدة القديمة). الرجوع = نوقف السيرفر ونشغّل LaunchAgents.

## التكلفة (تقديرية، الأسعار لازم تتأكد وقت الشراء)

### السيرفر
الـ render لفيديو 1080×1920 (assembly + upscale محلي + ffmpeg) هو الحمل التقيل. محتاجين CPU مش بس رام.

| الخيار | المواصفات التقريبية | تقريباً في الشهر |
|---|---|---|
| **موصى به: 4 vCPU / 16GB / 200GB NVMe** (Hostinger KVM 4 أو Hetzner CPX/CCX المشابه) | يكفي worker واحد + البورتال + الداشبورد | **$15–30** |
| بديل أضعف: 2 vCPU / 8GB (زي سيرفر Postiz) | الـ render أبطأ ويضغط على الباقي | $9–15 |
| أقوى للتوسع: 8 vCPU / 32GB | لما عملاء يزيدوا ويبقى فيه أكتر من run | $40–70 |

### باقي البنود
| البند | تقريباً |
|---|---|
| تخزين الأرشيف على R2 (10GB دلوقتي، +~5–10GB/شهر) | أقل من $1–2 في الشهر، وصفر egress |
| نسخ احتياطي (R2 10GB مجاناً، وبعدين نفس السعر) | ضمن اللي فوق |
| Tailscale، healthchecks.io، Cloudflare Tunnel | مجاني |
| الموسيقى بدل VODER (ElevenLabs music) | حسب الاستخدام، يتحاسب على رصيد المشغّل أو العميل |
| مفاتيح العملاء (OpenRouter، MUAPI وغيره) | **مش تكلفة المصنع.** العميل بيدفعها من حسابه |

### الإجمالي
- **تكلفة شهرية ثابتة: حوالي $17–35** (سيرفر + تخزين)، بالإضافة لسيرفر Postiz الحالي (~$9–15).
- **تكلفة لمرة واحدة**: وقت الشغل فقط (مفيش ترخيص). لو اشتريت السيرفر على مدة سنتين السعر بينزل لكن بيتطلب دفع مقدم كبير. الأفضل شهري في الأول.
- الوفر: مفيش. ده مش لتوفير فلوس، ده لإزالة نقطة الفشل الواحدة وإنك تقدر تاخد عملاء من غير ما جهازك يكون شرط.

## المخاطر

- SQLite كاتب واحد: لو عملاء كتير جداً، يبقى لازم Postgres (مرحلة تانية، مش دلوقتي).
- الداشبورد بدون login: لو اتفتح على النت العام هيكون ثغرة. لازم Tailscale بس.
- أي تغيير في `providers/*_adapter.py` بيكسر الـ checksum (راجع ذاكرة المشروع): بعد النقل نشغّل `scripts/supersede_changed_adapters.py --apply` لو اتعدّلت.
- انقطاع بين التبديل والتأكد: لذلك نبدّل وقت ما مفيش run شغال، والماك يفضل جاهز.
