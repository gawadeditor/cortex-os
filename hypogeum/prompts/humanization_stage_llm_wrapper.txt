HUMANIZATION STAGE — LLM WRAPPER INSTRUCTIONS

You will be given the Humanizer skill definition below this instruction block (unmodified, verbatim, exactly as published upstream). Apply it to a single narration beat from a documentary-style YouTube episode script. This is an unattended, single-shot, non-interactive pipeline call — not an interactive editing session.

The skill definition below was written for interactive editing sessions. In THIS call:

1. **No clarifying questions.** You may not ask the user anything. Do not invoke or reference AskUserQuestion. Proceed directly to rewriting the text you are given.
2. **No voice sample.** No writing sample will ever be provided for voice calibration. Skip the "Voice Calibration" step entirely and fall back to the skill's own documented default behavior.
3. **Documentary narration register.** This text is narration for a factual, encyclopedic documentary episode, not a blog post, essay, or personal opinion piece. Per the skill's own PERSONALITY AND SOUL section ("For encyclopedic, technical, legal, or reference text, neutral and plain *is* the correct human voice"), keep a neutral, plain, factual documentary tone. Do not inject first-person opinion, humor, or editorializing.
4. **Exact scope.** Rewrite only the single narration beat provided. Do not add new claims, facts, names, dates, numbers, or sentences beyond what the input already states. Do not shorten by dropping content — cover everything the input covers, per the skill's own "Rewrite, don't delete" rule.
5. **Non-negotiable preservation constraints** (in addition to, never overriding, the skill's own patterns):
   - Every name, date, number, percentage, and quoted phrase in the input must still appear in your rewrite.
   - Every URL and citation in the input must still appear in your rewrite.
   - Uncertainty/hedging language present in the input (e.g. "may," "could," "appears to," "according to") must still be present in some form in your rewrite — soften or reword it, never delete it outright, per the skill's own corrected §24 example ("could potentially possibly be argued that... might" → "may," not simply removed).

   - No em dashes (—) or en dashes (–) in the output, per the skill's own §14 hard constraint.
6. **Output format — structured JSON only.** Do not use the skill's own documented "draft → still-AI bullets → final rewrite" delivery format. Do not include any process commentary, explanation, draft, or bullet list in your response. Respond with exactly one JSON object and nothing else — no markdown code fence, no leading or trailing text:

   {"humanized_text": "<the final rewritten narration beat text>"}

   If, after careful review, the input already reads as natural human writing and needs no change, return it unchanged in the same JSON shape: {"humanized_text": "<the original text, unchanged>"}.
